# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"CARVE LINE" — a browser snowboard downhill game. The game (HTML, CSS, JS) lives in `index.html` (~3100 lines); the only other runtime file is `downhill-music.js` (dynamic music engine, loaded as a classic `<script>` before the module, exposes the global class `DownhillMusic`). No build step, no package.json, no tests, no linter, no git repo.

- Three.js r0.186.1 + addons are loaded from jsDelivr via an `<script type="importmap">`; the game code is one `<script type="module">`.
- UI text and code comments are in **German** — keep new strings/comments in German to match.
- Everything is procedural: characters (built from primitives), trees, buildings, terrain, canvas textures, audio.
- Visual style is **comic / cel-shaded**: right after the imports, `THREE.ShaderChunk.lights_physical_pars_fragment` is patched so direct light goes through `toonNL()` (3 hard steps) for every Standard/Physical material; ambient/IBL stays soft. An `OutlineShader` pass draws ink lines from depth discontinuities (Laplacian of inverse depth). Terrain is marked in the color buffer's alpha (snow shader writes `gl_FragColor.a = 0.5`); a full line is only drawn when the *nearest* surface at the edge is a non-terrain object, so slope crests/horizon get just a faint near line. Keep other opaque materials at alpha 1. Because the toon steps swallow the corduroy normal map, `makeSnowMaterial` also uses the normal map's rib slope (`mapN.x`) as a bluish color hatching on groomed snow, faded out with distance.

## Quartex-Pascal-Port (`qtx/`)

`qtx/CarveLine/` is a complete port of the game to Quartex Pascal (log: `qtx/PORTING.md`, English). The game logic is in `qtx/CarveLine/units/carve.*.pas` (one unit per former JS class group, including the music engine `carve.music.pas`); `index.html` there keeps the original markup/CSS plus a small ES-module loader that puts `THREE` + addons on `window` and calls the Pascal `main()`. Build only through the Quartex IDE (MCP on `localhost:3030`: `set_file` the units, then `compile`); `index.js` is build output. Changes to the JS game should be mirrored there. Pascal traps to watch: case-insensitive names (JS pairs like `T`/`t`, `dT`/`dt` must be renamed), reserved words (`set`, `type`, `repeat`, `shl`, `shr`, `on`, `lambda`, `low`, `swap`), all locals become one function-scoped JS `var` (no per-iteration closures in loops — use a helper function), and anonymous-class field initialisers must not reuse the field name on the right-hand side.

## PWA

The game is an installable, offline-capable PWA: `manifest.webmanifest`, `sw.js`, `icons/` (generated PNGs). All paths are relative so every version folder (`Version1/`, `Version2/`, …) is its own app with its own cache (`sw.js` names the cache after its scope path and ignores requests outside its folder). Caching: page network-first, own files cache + background refresh, `cdn.jsdelivr.net` (three.js) cache-first. The SW is only registered over HTTPS or on localhost. A version folder needs `index.html`, `downhill-music.js`, `manifest.webmanifest`, `sw.js` and `icons/`.

## Running

ES modules require HTTP (not `file://`). Serve the folder and open it in a browser, e.g.:

```
python -m http.server 8000   # then open http://localhost:8000/
```

Runtime errors are shown in the red `#err` overlay (global `error` listener at the bottom of the script). The running instance is exposed as `window.game` for console debugging.

## Architecture (inside the module script, top to bottom)

- **`CONFIG`** — all tuning constants (physics, rider/board, skier AI, scoring, camera, world). Tweak gameplay here rather than hard-coding numbers.
- **`PRESETS`** (`low`/`medium`/`high`) — graphics quality (pixel ratio, shadow size, bloom, SMAA, snowfall, tree count, chunks ahead, particles). Auto-downgrade based on `CONFIG.autoPresetFps`. `MAX_TREES`/`MAX_CHUNKS` size the pools.
- **Tracks**: `TRACKS` (classic/wald/nordwand) parametrize `Course` (sine-term sums for centerline `cx`, half-width `w`, grade `g`, plus length, kicker grid, forest density). The active track `TRACK_ID` is read from `carveline.settings` at startup; switching tracks saves the setting and reloads the page (the world is built once per track). Per-track storage keys via `storeKey('best'|'ghost')` (classic keeps the legacy unsuffixed keys). Lifts/huts are placed relative to `course.zf`.
- **`Course`** — the analytic slope definition: centerline `cx(z)` (+ derivatives), half-width `width(z)`, grade and height `y0(z)`/`height(x,z)`. Everything (terrain, physics, AI, camera ground clamp, ragdoll) queries the course, so changes here ripple everywhere. The run goes along +z to `CONFIG.courseLength`, followed by a run-out.
- **World**: `Terrain` (chunked streaming mesh ±`chunkHalfWidth` with pooled chunks, trees/rocks, LOD by `lodDistance`), `Mountains`, `makeGate`, `Snowfall`, `makeSnowMaterial` (custom shader sharing the `SHARED` uniforms). Off-piste the terrain is an open slope (rising on −x side, falling toward the valley on +x) with hills — no side walls; trees are sparse near the piste and form forest bands farther out (noise mask). `Mountains` is a camera-following ring (starts right behind the terrain strip, inner edge pulled down as a skirt so there is never a gap) with three staggered ranges of individual peaks (cones broken by spur noise) over a hilly valley floor with forest belts; own per-range haze (`fog: false`) so peaks stay visible. The ring follows the camera at rider height, so its floor is sheared in the vertex shader by the course's average grade (`Mountains.update(..., grade)`) — otherwise the mountains float above the valley mid-run.
- **`Resort`** — static, built once (deterministic RNG): 3 chairlifts (stations, pylons raised until the cable clears the ground, sagging cables as `LineSegments`, chairs animated along the loop in `update(dt)`), mountain huts with terraces, scattered houses (mostly on the uphill −x side), a hamlet with church on an uphill terrace mid-run, and a town with church on the flat run-out below the finish. Building types (index = `houses[].type`): chalet, small chalet, hut, church (`makeChurch`), farmhouse (`makeFarmhouse`), hotel, hay barn, plastered chalet — built from `makeChalet`/`addGableRoof`/`addWindows` (merged boxes with vertex colors). Placement note: anything more than a little below the piste on the valley (+x) side is hidden behind the slope — put visible set pieces uphill or at the run-out. `clearings` keep trees out of villages/sightlines (houses ignore them via `blocked(..., false)`); `updateVisibility()` hides houses beyond the streamed terrain so they don't float. `obst` circles drive rider collisions (`crash('obstacle')`); `blocked()` keeps trees/rocks/houses off buildings and lift corridors.
- **Rider pipeline**: `Input` (keyboard + gamepad + touch → smoothed steer/tuck/brake/jump; touch UI `#touch` in the HUD — left stick with analog steer / up = tuck / down = brake, right jump/cam/pause buttons — shown only when `body.touch` is set — on `(pointer: coarse)` or on the first real touch `pointerdown`, not merely `maxTouchPoints`) → `RiderPhysics` (fixed-step board physics, edge/grip/sidecut model, ollie, air spin, landing/crash detection; emits events via `onEvent`) → `RiderAnimator` (procedural 17-joint skeleton `J`/`NJ`, 2-bone IK via `solveIK`) or `Ragdoll` (verlet on crash) → `Rider` (mesh posed from joint positions).
- **Chibi characters**: proportions live in `RIG` (short legs, big head ~0.28 m radius) and are used by `RiderAnimator`, the skier pose in `SkierAI.render`, `Ragdoll`, `boardFromJoints` and helmet cam; fixed colors in `FIG.colors`. `Rider` is a set of meshes (thick limb segments, puffer torso, head group with helmet/strap/goggles/hair) positioned from the 17 joints each frame; `rider.head` is hidden in helmet cam. The board's orange tips are done in its material shader by local x, not vertex colors.
- **Nets**: the curve-outside safety nets (`Course.netSide`) block the riding rider in `RiderPhysics` and the `Ragdoll` (points are clamped to the net line with a small bounce and friction, so a crashing body slides along the net).
- **Getting unstuck**: holding tuck below ~5 m/s pushes the board forward (`CONFIG.pushAcc`, skating), enough to climb kicker ramps/rollers from standstill; after a crash `Course.safeZ()` moves the stand-up point downhill off kickers/rollers and the rider restarts with ~3 m/s (same for rivals). `land()` only checks yaw-vs-velocity when horizontal speed > 3 m/s (standing ollies used to crash on a random velocity heading).
- **Tricks** live in `RiderPhysics`: air-time `flip` (W/S, only armed after re-pressing post-takeoff so holding tuck doesn't flip) and `grab` (E/Shift, pad X/RB, touch button); `land()` crashes on >`landFlipCrash` residual flip and stores `lastTrick` for `Score.onAir`. Visually the flip is `rotateRiderPose()` around the rider's lateral axis; the grab is a pose in `RiderAnimator`. `Game.updateTrickHint()` is the in-air landing assistant (`#trick` ring): it predicts touchdown time from the ballistic path vs. terrain and the final flip/spin angle for “release now” (rate decays, k=9 flip / 6 spin) vs. “keep holding” (rate ramps to full), then recommends in priority order clean > safe abort > risky completion (texts: Loslassen!/Abbrechen!/Weiterdrehen!/Knapp/Sturzgefahr!). No text in the first 0.15 s of air.
- **`poseFromState(anim, st, dt, wj, boardPos, boardQ)`** is the shared joint/board computation used by the player (`renderRider`), `Ghost` and `Rival` — keep it the single source of truth for rider posing.
- **`Ghost`** records the run at 20 Hz (`GHOST_F` floats per sample: pos, board up, yaw, animator inputs, flip, grab, visibility), saves it base64 in localStorage on a new best, and replays it as a translucent `Rider`.
- **`Rival`** (2 AI boarders from `RIVALS`) runs its own `RiderPhysics` with a look-ahead line-following controller (`think()`), respawns after crashes, and feeds the live/final placement. `Game.updateTags()` shows a small HTML name tag (jacket-color dot) above each rival, projected from its head joint and faded by distance. `Game.contacts()` handles body contact each frame (capsules via `segSegDist`): player↔rival and rival↔rival bumps push apart and equalize velocity along the contact normal; closing speed above `CONFIG.bumpCrashSpeed` knocks down whoever rams (player crash reason `rival`). Rivals dodge skiers ahead in `think()` but can still hit them (`SkierAI.checkHit`).
- **`Challenges`**: slalom gates (bonus / `gatePenalty` seconds, flags recolor on pass/miss; gates skipped while crashed count as missed) and collectible stars, all deterministic from the course.
- **Options** in `game.opts` (ghost, rivals, time of day, weather, rider colors) are persisted inside `carveline.settings`; `applyAtmosphere()` sets sun/sky/hemisphere/fog, fades the mountains (`Mountains.setFade`) and switches the snowfall storm mode, then rebuilds the IBL env map.
- **`SkierAI`** — NPC skiers with their own procedural animation, rendered entirely with `InstancedMesh` parts (per-instance colors for jacket/pants/helmet). Capsule distance (`segSegDist`) for collisions and near-miss callbacks (`onNearMiss`).
- **Music**: `AudioEngine.init()` creates `DownhillMusic` on the shared AudioContext, reroutes its master into the game's music bus (volume slider) and mutes its own wind (the game has wind SFX). `Game.loop` feeds `musicIntensity()` each frame (speed, combo, air, slow-mo, final 15 % boost); stingers: `musicFall()` on crash, `musicOvertake()` on near miss / passing a rival, `musicFinish()` at the finish line, `musicRestart()` on run start/title. If `downhill-music.js` is missing, the old built-in `AudioEngine.schedule()` loop plays instead.
- **Feedback**: `ParticleSystem`, `Trail`, `CameraRig` (3 modes: `CAM_NAMES`, speed-based FOV/shake), `AudioEngine` (WebAudio, procedural), `HUD`, `Score` (combos, near-miss/carve/air/spin points).
- **`Game`** — owns everything. State machine `title → countdown → play → finished` plus `paused`; `riderMode` is `ride | ragdoll | standup`. `loop()` runs a fixed-timestep accumulator at `CONFIG.physicsHz` (max `maxSubSteps`), with `timeScale` for near-miss slow-mo, then renders with interpolation (`prevPos`/`pos`, `alpha`) through an `EffectComposer` post chain.

## Conventions

- Hot loop is allocation-free: reusable `THREE.Vector3`/`Quaternion` scratch objects are created in constructors (`this.tmp`, `this.capA`, …). Don't `new` objects per frame.
- Code style is dense: many statements per line, short names. Match it. Careful when appending `// comments` to such lines — everything after them on the line is dead.
- Post chain: `RenderPass → OutlineShader → UnrealBloomPass → GradeShader → SMAA → OutputPass`. The composer's two render targets get a `DepthTexture`; the outline pass reads `readBuffer.depthTexture` (wrapped `render`), so it must stay directly after the `RenderPass`. Tone mapping happens in `OutputPass`, so `GradeShader` works on linear HDR values (>1 possible) — keep its curves monotonic for all positive inputs. Bloom threshold is 3.2 on purpose: low sun makes snow and sky halo exceed ~2 over large areas and would white out the frame; `clampSky` caps the sky at 2.2.
- Short screens (`@media (max-height:520px)`, e.g. phone landscape with browser bars ~300 px): the title becomes a two-column grid (controls left, help right, no subtitle), options/finish cards become two-column with a sticky button row. The error overlay ignores detail-less cross-origin "Script error." events and closes on tap.
- Persistence via `localStorage` keys `carveline.settings` (preset, auto, volumes, camera mode) and `carveline.best` (best time/score); always wrapped in try/catch.
